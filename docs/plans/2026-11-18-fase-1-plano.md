# Fase 1: fatia vertical publicada (plano de implementação)

> **Para agentes executores:** sub-skill obrigatória:
> superpowers:subagent-driven-development (recomendada) ou superpowers:executing-plans,
> tarefa por tarefa. Os passos usam caixas (`- [ ]`) para acompanhamento.

**Objetivo:** entregar o LGPD-Scan v0.1.0 no PyPI: `scan` e `anonymize --mode mask` sobre
CSV, com detectores de CPF, CNPJ (inclusive alfanumérico), e-mail e telefone.

**Arquitetura:** pipeline em camadas, `readers` → `detectors` → `scoring` → `report` /
`anonymize`, com a CLI em `argparse`. O `scoring` faz duas passagens: a primeira agrega por
(coluna, tipo) e decide a regra da maioria; a segunda (só no `anonymize`) reescreve o
arquivo com a mesma decisão. Nenhuma estrutura guarda o valor pessoal: as ocorrências
guardam só posições.

**Stack:** Python ≥ 3.11 (dev 3.14) · `uv` + `uv_build` · `argparse` (biblioteca padrão) ·
Rich 15 · pytest · mypy strict · Ruff · GitHub Actions + Trusted Publishing.

**Spec:** `docs/design/2026-11-18-fase-1-design.md`. Ler junto com este plano.

## Restrições globais

- `requires-python = ">=3.11"`. Desenvolvimento local **só** com o Python 3.14 do `uv`;
  o `python` 3.11 do PATH nunca roda neste projeto (caminho com acento; ADR-0001).
- Dependência de execução **única**: `rich>=15.0.0,<16` (versão exata travada no `uv.lock`; faixa no `pyproject.toml` para não conflitar no ambiente de quem instala). CLI em `argparse` (ADR-0003). Nenhuma
  outra dependência de execução sem ADR.
- Build: `requires = ["uv_build>=0.13.9,<0.14"]`, `build-backend = "uv_build"`.
- Nenhum módulo do pacote importa `socket`, `http`, `urllib` ou `requests`; a suíte inteira
  roda com `socket.socket` bloqueado (Tarefa 2).
- Nenhuma saída (stdout, stderr, JSON, mensagem de erro, exceção) contém um valor pessoal
  completo nem o conteúdo de uma célula. Erros citam linha e coluna.
- Dados de teste só sintéticos, gerados por código (`lgpd_scan._sinteticos`, Tarefa 3) ou
  vetores oficiais da Receita. Nunca CPF/CNPJ copiado da internet.
- Mensagens, ajuda e nomes de domínio em português. Textos embutidos do `argparse`
  (`usage:`, `error:`) ficam como estão.
- Códigos de saída (contrato público): `scan` → `0` risco nenhum/baixo, `1` risco
  médio/alto, `2` erro; `anonymize` → `0` sucesso, `2` erro. `argparse` já sai com `2` em
  erro de uso.
- `LIMIAR_MAIORIA = 0.5`.
- Actions pinadas por SHA com a tag em comentário, como no `ci.yml` atual.
- Protocolo do `CLAUDE.md`: **uma tarefa = uma branch curta = uma PR**; o usuário faz o
  squash merge; esperar "próximo" entre tarefas; gravar/executar só após "pode executar".
- Commits em Conventional Commits, pt-BR, **sem** linha de coautoria.
- Comandos de verificação local: `uv run pytest`, `uv run mypy`,
  `uv run pre-commit run --all-files`. Todos verdes ao fim de **cada** tarefa (R11:
  checar o estado da tarefa, não só o final).

## Foco de revisão

Entradas que o spec implica mas não nomeia, e que mais provavelmente quebrariam o uso real:

1. **Linhas irregulares** (menos ou mais células que o cabeçalho): faltantes contam como
   vazias, excedentes entram como `coluna_N`, sem quebrar. Teste na Tarefa 8.
2. **Cabeçalho com nomes repetidos** (duas colunas `telefone`): a agregação usa o
   **índice** da coluna, não o nome. Teste nas Tarefas 9 e 10.
3. **Célula entre aspas com quebra de linha ou `;` dentro**: a leitura com `newline=""`
   preserva o conteúdo, e o `anonymize` reescreve com a mesma citação. Teste na Tarefa 11.
4. **Campo gigante** (> 131.072 caracteres, o limite padrão do módulo `csv`): o leitor
   eleva o limite para `2**31 - 1` e o arquivo é lido. Teste na Tarefa 8.
5. **Saída que aponta para a entrada por outro caminho** (relativo × absoluto, maiúsculas
   no Windows): comparar com `Path.resolve()` e `os.path.samefile` antes de abrir para
   escrita. Teste na Tarefa 11.

```python
    encoding: str  # "utf-8-sig" | "cp1252" | o informado
    delimitador: str  # "," | ";" | "\t" | "|" | o informado


class LeitorCsv:
    def __init__(
        self, caminho: Path, *, encoding: str | None = None, delimitador: str | None = None
    ) -> None: ...

    formato: FormatoCsv
    cabecalho: list[str]  # nomes; duplicados preservados

    def linhas(self) -> Iterator[list[str]]: ...  # reabre o arquivo a cada chamada
```

  `linhas()` devolve cada linha com exatamente `len(cabecalho)` células quando faltam
  (completa com `""`). Quando sobram, o `cabecalho` ganha `coluna_N` na primeira passagem
  completa; para isso, o construtor faz uma passagem de validação que decide a codificação
  e mede a largura máxima.

- [ ] **Passo 1: testes que falham** (arquivos criados em `tmp_path` com dados sintéticos):
  - UTF-8 com BOM e `,` → `formato == FormatoCsv("utf-8-sig", ",")`, cabeçalho sem o BOM;
  - cp1252 com `;` e `"Joaçã"` no conteúdo → `FormatoCsv("cp1252", ";")`, texto correto;
  - `encoding="latin-1"` e `delimitador="|"` informados → respeitados;
  - linha curta completada com `""`; linha longa gera `coluna_4` *(Foco 1)*;
  - campo com 200.000 caracteres é lido *(Foco 4)*;
  - arquivo vazio → `cabecalho == []`, nenhuma linha; só cabeçalho → nenhuma linha;
  - bytes inválidos em cp1252 (`b"\x81"`) → `ErroLeitura` cuja mensagem **não** contém o
    conteúdo da linha e sugere `--encoding`.
- [ ] **Passo 2:** FAIL. **Passo 3:** implementar. `csv.field_size_limit(2**31 - 1)`;
